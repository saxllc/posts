The Core Insight

Rethinking who owns the transaction narrative

The user's semantic journey—not just transaction data—should persist as a user-owned artifact. "I want to invest ₹10,000 in HDFC Flexi Cap" is captured not as database entries scattered across systems, but as a traceable, human-readable narrative that accompanies the transaction through all handshakes.

📱

🔐

🔗
Cross-Org Portable
Asserts truth across organizational boundaries with cryptographic attestation.

Introducing: FinContext Vault

A DigiLocker-style extension for financial transaction context

FinContext Vault is a user-owned, encrypted store that captures the semantic trace of every financial interaction—forms filled, confirmations received, statuses observed—creating a single source of truth that travels with the user.

Groww's Rhetorical Interface

Context-aware dispute resolution and explanation layer

POST /rhetorical/dispute

Accept structured context trace from FinContext Vault

{
  "vault_entry_id": "fin_ctx_2025_...",
  "attestation": { ... },
  "disclosed_fields": ["intent", 
    "confirmations", "discrepancy"]
}
GET /rhetorical/explain/{journey_id}

Return human-readable explanation, not just status code

{
  "status": "RECONCILIATION_DELAY",
  "explanation": "Payment received but 
    settlement batch processing delayed...",
  "action": "Manual allocation initiated",
  "eta": "4 hours"
}
POST /rhetorical/resolve

Commit to SLA with tracking for user's vault

{
  "commitment_id": "res_2025_...",
  "sla_hours": 24,
  "tracking_url": "...",
  "signed_commitment": { ... }
}

Resolution Flow with Vault

1
User's AI detects discrepancy
"Bank and Razorpay confirm success, but Groww shows failure"
2
User authorizes disclosure to Groww
Vault sends signed context trace via /rhetorical/dispute
3
Groww's Rhetorical Interface verifies
Cross-checks vault attestation against: internal logs + Razorpay API + BSE settlement
4
AI generates explanation response
"Payment received. Reconciliation delay caused failure message. Initiating manual allocation at Oct 10 NAV."
5
Resolution logged to user's Vault
Complete audit trail: discrepancy → assertion → verification → resolution

Not "Please wait while we investigate" → but "Here's exactly what happened and when you'll be resolved"

Vault Access

Full context access • Can query all confirmations • Receives AI-generated discrepancy alerts

💳 SECONDARY: Razorpay, BSE MF Orchestration Layer

Responsibilities

Payment orchestration • Order routing • B2B SLA with Groww • Settlement confirmation

Vault Access

Transaction-specific only • Their own confirmation entries • On-demand via Groww request

🏦 TERTIARY: Bank, AMC, RTA Regulatory Anchors

Responsibilities

Source of truth for funds • Product allocation • Folio registry • RBI/SEBI regulated

Vault Access

Attestation only • Hash + timestamp proof • No content access • Dispute audit trail

🔑 Key UX Principle

User should never contact Bank or RTA for a Groww transaction. Groww, as primary, has contractual authority and API access to resolve disputes by querying downstream partners. The Vault enables user to assert context, not chase it.

Implementation Pathways

Who builds what, and strategic questions ahead

Who Builds the User-Side Vault?

🏛️
India Stack Extension DPI Native

DigiLocker + Account Aggregator + "Transaction Context" layer. Citizen-owned, government-enabled, interoperable across all platforms. The recommended long-term architecture.

📱
Groww-Provided Vault First Mover

Groww offers FinContext Vault as a premium feature. Portable via export, but Groww-hosted. Competitive moat for trust-conscious users. Can establish de facto specification.

🍎
OS-Level Integration Long Term

Google/Apple integrate into Wallet/Health-style apps. Highest integration, but platform lock-in and global rollout delays. Less likely for India-specific financial context.

💡 Recommended Hybrid Approach

Groww pilots as first-mover (Option 2), with export format compatible with eventual India Stack standard (Option 1). Establishes de facto specification while building competitive advantage.

Open Strategic Questions

1. Incentive Alignment
Why would Groww invest in context-aware resolution? Answer: 100M+ users from Tier 3/4 with higher dispute sensitivity. Trust = retention moat.
2. Regulatory Clarity
Is AI-generated context trace admissible in SEBI disputes? Path: Pilot with attestation standards from IT Act §65B.
3. Partner Adoption
Will Razorpay/BSE expose Rhetorical APIs? Path: Start with Groww's own internal systems, then partner APIs.
4. Privacy Guarantees
Device-first processing + encrypted sync + selective disclosure. User never loses control of their context.
