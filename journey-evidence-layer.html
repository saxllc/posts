Journey Evidence Layer

Architecture Design Document v1.0

DPI Digilocker DEPA

Executive Summary

The Journey Evidence Layer is a DPI-based architectural pattern that bridges the gap between payment initiation and ownership verification by creating a verifiable chain of transaction evidence.

🏦

Digilocker as Vault

Transaction Verifiable Credentials repository

🔄

DPIx as Orchestrator

Agent coordinating Aadhaar, UPI, and services

🔐

DEPA for Consent

Privacy-preserving evidence sharing

The Payment-Ownership Gap

⚠️ The Problem

  • 1. User pays via UPI → Money debited ✓
  • 2. Payment gateway confirms → Email sent ✓
  • 3. Service delivery fails → Webhook timeout ✗
  • 4. Evidence scattered → User has SMS/email, system can't ingest ✗

✓ The Solution

  • → Capture payment confirmations at source
  • → Store as verifiable credentials in Digilocker
  • → Share via DEPA consent when needed
  • → Resolve disputes in minutes, not days

📊 Real-World Case: Groww Investment Failure

Step 1: User Initiates

₹10,000 investment via Net Banking

Step 2: Bank Debits

Deutsche Bank confirms debit

Step 3: Gateway OK

Razorpay sends confirmation email

Step 4: Groww Fails

Webhook timeout, no units allocated

Current State: User has email/SMS proof, but Groww system has no mechanism to ingest it. Resolution takes 7-14 days through manual reconciliation.

Security & Privacy

🔐 Private Spaces

  • → User-controlled encryption (key derived from passphrase/biometric)
  • → Evidence stored in encrypted container
  • → Decryption only on-device when user accesses
  • → Recovery via social MPC (multi-party computation)

🛡️ DEPA Consent

  • → Purpose-limited access (e.g., "Investment reconciliation")
  • → Time-bound (7-30 days depending on use case)
  • → Granular field selection (only share required data)
  • → Revocable at any time by user

⚠️ Mitigating Single Point of Failure (SPOF)

Backup to User Storage

Export encrypted evidence to user's cloud (Google Drive, iCloud)

Multi-Issuer Model

Service providers also store evidence, cross-verify with Digilocker

Blockchain Anchoring

Hash stored on public blockchain for tamper-proof timestamp (future)

High Priority Mitigations

  • → SPOF: Private Spaces + backups
  • → Intent unavailability: Use existing eKYC providers
  • → Adoption friction: Gradual rollout, high-value use cases first

Medium Priority Mitigations

  • → Latency: Async architecture, don't block main flow
  • → Privacy: E2E encryption, consent management
  • → UX: User testing, iterative refinement

Implementation Roadmap

Phase 1: Foundation

Months 1-3
  • □ Define Transaction Evidence schema with NPCI/UIDAI working group
  • □ Implement Private Spaces in Digilocker (POC)
  • □ Build DPIx agent prototype (Android, integrate with UPI)
  • □ Partner with eKYC provider for Aadhaar auth (interim solution)

Phase 2: Integration

Months 4-6
  • □ DEPA consent flow implementation with AA (Account Aggregator)
  • □ On-device AI for receipt parsing (integrate SLM like Gemma Nano)
  • □ Pilot with one service provider (Groww or PhonePe)
  • □ Implement backup/recovery mechanisms (MPC-based social recovery)

Phase 3: Scale

Months 7-12
  • □ Multi-service provider integration (investment, insurance, e-commerce)
  • □ Analytics dashboard for journey completion rates
  • □ Advocate for native Aadhaar auth intent API with UIDAI
  • □ Public launch with marketing campaign

Key Insights

💡

Standardization as Public Good

Transaction evidence should be treated as a public utility—standardized formats, interoperable across providers, user-controlled like identity and payments.

🎯

DPIx as Orchestrator, Not Store

DPIx doesn't compete with Digilocker—it's the intent weaving agent that makes the entire journey coherent, capturing evidence and writing to the vault.

🔐

Privacy by Design

Private Spaces with user-key encryption ensure that even if Digilocker is compromised, sensitive transaction evidence remains protected.

⚡

Minutes, Not Days

By making evidence machine-readable and consent-accessible, dispute resolution time drops from 7-14 days to minutes.
